# 参考图摄取与复刻（ingest）

> 目的：把用户给的**参考图**转成可编辑 CAD 图纸。**先判输入类型，再选工具**——这是本模块的核心纪律。

## 〇、总纲：参考图**不一定**遵守本技能约定

下一张参考图可能是**别的标准**（非国标 / 甲方图 / 国外图 / 手绘 / 照片）、
**别的墙体表示法**（斜线填充 / 彩色 / 单线 / 双线）、**没有尺寸标注**，
甚至**不是平面图**（立面 / 剖面 / 大样 / 机电 / 总平面）。所以：

**两条路线：一条保底，一条加分。**

| 路线 | 依赖 | 能否应对"非本技能约定" |
|---|---|---|
| **忠实转绘** `pdf_to_dxf.py` | 只依赖"输入是矢量" | ✅ **通用兜底**——看不懂也能原样复刻 |
| **理解型重建** `classify_walls.py` 等 | 依赖图纸约定（墙怎么画、比例、图幅） | ⚠️ 必须先探测约定；探测不出就**问用户** |

**硬规矩：**

1. **绝不把本技能的取值当通用前提**——轴网 17200、墙厚 200、比例 1:100…… 都是"那张图"的，不是"所有图"的。
2. **先体检，再决定**：任何参考图到手，先跑 `scripts/ingest/probe.py`，拿到类型 / 线宽 / 填充 / 字号 / 比例 / 尺寸 / 图别线索。
3. **不确定就问，不要假设**：**出图比例、墙体表示法、是否需要参数化**——这三项探测不出来时必须问用户。
4. **永远留兜底**：理解不了就退回**忠实转绘**（矢量）或**描线**（位图），保证"至少能拿到一份可编辑的图"。
5. **位图更不确定**：照片 / 斜拍 / 低清扫描，先做去噪与纠偏；实在不行，明确标注为"仅供描摹参考"。
6. **三条读图通道不许混用**（见下节）——尤其**不许拿"看图"去量尺寸**。

### 三条读图通道（心智模型，别混用）

| 通道 | 干什么 | 精度 | 用途 |
|---|---|---|---|
| **读数据** | 矢量 PDF：`get_drawings()` 取 `l`/`c`/`re`/`qu` 路径坐标 | **几何级 1:1** | 主力，能复刻就复刻 |
| **图像处理** | 位图：二值化 → 按线宽形态学分层 → `findContours` → 矢量化 | 取决于分辨率 | 位图唯一正路 |
| **视觉判断** | 模型自身的多模态视觉 | **语义级，量不出尺寸** | 只用认图别、判布局、选参数 |

> **铁律**：视觉通道**只做定性决策，绝不参与定量的几何**。
> 拿"看图估计"去复刻精确图纸，是本技能历史上"墙体不完整"的根因（见 `pitfalls.md` A1）。

## 一、输入分流（第一步，必做）

| 输入 | 判据 | 走哪条路 | 保真度 |
|---|---|---|---|
| 矢量 PDF | 用 PyMuPDF 打开后 `page.get_drawings()` 有大量路径、`get_images()` 为空 | `ingest/pdf_to_dxf.py` **矢量转绘** | **几何级 1:1** |
| 扫描/截图 PDF、JPG、PNG | 只有一张位图；或 `get_drawings()` 几乎为空 | `ingest/raster_to_dxf.py` 描线 | 中（取决于分辨率与标定精度） |
| DWG/DXF | 直接是 CAD 文件 | 直接读，无需摄取 | 无损 |

判断代码（一行结论）：

```python
import fitz
p = fitz.open(path)[0]
print(len(p.get_drawings()), len(p.get_images()))   # 路径多、图少 => 矢量
```

> **铁律：是矢量就别渲染成图再"目测"。** 渲染成位图再描线，等于把精确坐标降级成像素估计，是精度自残。

## 识图六步法（人工读图流程，先走一遍再动手）

> 来源：《三维识图一本通·建筑平面图的识读方法》2026-10-17 收录。
> **机器读图前先用这套流程过一遍**——它能在动手前判断"这是什么图、缺什么、能不能复刻"。

| 步 | 做什么 | 得到什么 |
|---|---|---|
| ① | **看图名、比例、图号** | 楼层、比例（决定尺寸换算）、图纸编号 |
| ② | **找定位轴线** | 位置与方向——横向为**数字**轴线、竖向为**字母**轴线，**交点为控制点** |
| ③ | **看墙体、柱、门窗、洞口** | 构件与开口——**粗实线=承重墙，细实线=非承重墙/隔墙** |
| ④ | **看尺寸、符号** | 尺度与标高——**总尺寸表示整体，分尺寸表示各部分**，单位 mm |
| ⑤ | **综合分析空间关系** | 完整空间概念：整体轮廓 → 空间划分 → 交通组织 → 功能判定 → 尺寸核对 |
| ⑥ | **复核检查** | 见下 |

**口诀：看图先看整体，再看局部细节；先定位空间，再理解结构。**

> 识图准备四件事：了解工程概况与设计说明、熟悉图纸目录及图号、
> 了解常用建筑符号和图例、**掌握图纸比例和单位（一般为 mm）**。

### 识图检查五条（复刻前自问）

1. 轴线尺寸是否正确、完整
2. 各房间名称、功能是否合理
3. 墙体厚度、门窗位置是否一致
4. 标高、标注、符号是否齐全
5. 与其他图纸（平、立、剖）是否相互吻合

> 四条注意事项：不要只看局部；不要忽略轴线和尺寸标注；
> **门窗编号必须对应门窗表**；**图纸之间有疑问时切勿贸然施工**——
> 这条对复刻同样适用：拿不准就退回忠实转绘，或问用户。

## 二、墙体识别：剪力墙 vs 隔墙（先分清，别把"填充"当成"墙"）

**最容易犯的错**：把"实心黑色填充"当成墙本身。实际上黑填充是 **poché（剖切图例）**，墙的几何来自**轮廓线**。

| 图示 | 是什么 | 几何来源 | 归层 / spec |
|---|---|---|---|
| **轮廓线 + 实心黑填充** | **钢筋混凝土剪力墙**（承重 / 抗震墙） | 取**轮廓**；黑填充另用 SOLID HATCH 表现 | `WALL-STR` / `walls[].type="structural"` |
| **双线轮廓，无填充** | 砌体**隔墙 / 填充墙** | 两条平行轮廓线 | `WALL-PAR` / `walls[].type="partition"` |

工具：`scripts/ingest/classify_walls.py`

```bash
python ingest/classify_walls.py 参考图.pdf 墙体.dxf --k 0.0066067 --x0 49.6 --y0 122.0
```

判据：某墙体区域**内部是否有实心填充**——有=剪力墙，无=隔墙。

**落 DXF 时轮廓与填充必须分层**（这一条同样适用于引擎出图）：

| 实体 | 图层 | 说明 |
|---|---|---|
| 墙的**轮廓**（多段线 / 直线） | `WALL-STR` / `WALL-PAR` | **几何本体**在这里 |
| 剖切**填充**（实心 HATCH） | **`WALL-POC`** | 只是图例，单独一层 |

> 关掉 `WALL-POC` 应当仍能看到完整的墙轮廓 —— 这是分层的意义。
> 详见 `layers.md`「轮廓与填充必须分开图层」。

**隔墙判据（收紧后，实测有效）**：双线轮廓必须**同时**满足

1. 每条轮廓线长 **≥ 500mm**（滤掉文字笔画、家具短边、尺寸箭头）；
2. 两条线**两端对齐**（端点差 ≤ 220mm）——确是同一条墙的两个面，而非两条无关线；
3. **不是线族**：同一方向上若存在"**连续 ≥3 条、间距相近（60~200mm）**"的平行线，
   整组判为**填充 / 楼梯踏步**并剔除——**墙只会是"恰好两条"**。

> 本图实测：收紧前 **280 段**（混入填充纹理与家具边）；收紧后 **43 段**，肉眼核对基本为真实隔墙。
> 判据写在 `scripts/ingest/classify_walls.py` 的 `comb_positions()` 与 `pair()` 里。

> 实务校验：本图填充带两端有轮廓线与之重合、厚度 200 与设计说明「墙厚200」一致，
> 证实是**剪力墙 poché**，而非"墙=填充"。
>
> ⚠️ 反面教训：若直接把填充带 bbox 当墙，会把剪力墙的**填充**误当整面墙，
> 且会漏掉"无填充的隔墙"；且组合墙（L/T 形）的填充 bbox 过大而被滤掉，导致"墙体不完整"。

## 三、矢量 PDF → DXF（首选）

`scripts/ingest/pdf_to_dxf.py`

```bash
python ingest/pdf_to_dxf.py 参考图.pdf 输出.dxf --k 0.0066067 --x0 49.6 --y0 122.0
```

### 标定（决定是不是 1:1）

1. 在图上找**最大一道总尺寸**（如 `17200`），量它两端尺寸界线在纸面的 x 差 Δx（mm）：
   `k = Δx / 17200`
2. 取**最左轴线**的纸面 x 作 `--x0`，**最下轴线**的纸面 y 作 `--y0`。

拿到 `k / x0 / y0` 后，脚本输出即为**模型毫米**，可直接量取真实尺寸。

### 输出图层

| 图层 | 内容 | 说明 |
|---|---|---|
| `REF-INK` | 描边路径 → LWPOLYLINE | 墙线、门窗、家具、尺寸线 |
| `REF-FILL` | 填充路径 → 闭合多段线 | 墙体涂黑、图案填充（可在 CAD 里再 HATCH） |
| `REF-TEXT` | 文字 → TEXT | 字高已换算到模型毫米 |

## 四、位图 JPG/PNG → DXF

`scripts/ingest/raster_to_dxf.py`

```bash
python ingest/raster_to_dxf.py 参考图.png 输出.dxf --mm-per-px 12.5 --wall-px 15
```

- `--mm-per-px`：量图上某道已知尺寸（如 3600）的像素长 L，则 `mm_per_px = 3600 / L`。
- `--wall-px`：墙厚像素数（≈ 墙厚 / mm_per_px）。核越大，只保留越粗的墙带。
- **文字不做 OCR**（避免重依赖）；文字需在 CAD 内对照补录，或另装开源 OCR 扩展。

### 位图路线为什么不如矢量

| 环节 | 位图 | 矢量 PDF |
|---|---|---|
| 坐标 | 像素整数，量化误差 | 精确浮点 |
| 线宽分层 | 靠形态学猜 | 路径属性直接给 |
| 文字 | 要 OCR，易错 | 文本层直接读 |
| 圆弧 | Hough 拟合，易断 | 贝塞尔控制点齐全 |

## 五、与"规格重建"路线的关系

本技能有两条复刻路线，用途不同：

- **转绘路线（本模块）**：`参考图 → DXF`，追求**像**。适合"照着这张图给我一份能编辑的图"。
- **规格重建路线**（`schema/drawing.spec.schema.json` + `pipeline.py`）：`需求/参考图 → spec → DXF`，追求**规范可编辑**。图框、轴网、尺寸链、门窗表由引擎按国标生成，改一处参数全图联动。

选择建议：
- 只要"一模一样、能编辑" → 转绘。
- 要"能改参数、按国标出图、送审签章" → 规格重建；复杂图形可先转绘拿到精确坐标，再据此写 spec。

## 六、复刻校验（1:1 判定）

**纪律：校验不能自己验自己。** 用产生结果的那套逻辑去校验结果，
同一次误读会在两边同时出现，比对恒为"一致"，**错误被完整掩盖**。

工具：`scripts/ingest/verify_clone.py` —— **不引用生成侧任何模块**，两条独立腿
（PyMuPDF 读参考图 / ezdxf 读复刻件），各自换算到模型毫米后叠加比对。

```bash
python ingest/verify_clone.py 参考图.pdf 复刻.dxf \
    --k 0.0066067 --x0 49.6 --y0 122.0 --out 输出目录 --json 报告.json
```

四路独立证据：

| 路 | 判据 | 通过线 | 独立性来自 |
|---|---|---|---|
| ① 几何覆盖率 | PDF 线段 ⇄ DXF 线段**双向**覆盖率 | ≥ 97%（< 90% FAIL） | 两条独立读取路径 |
| ② 尺度自校正 | 扫描 k，看最佳值是否偏离给定 k | ≤ 1% | 能抓出标定错误 |
| ③ 文字层 | 内容集合 / 数量 / 相对位置 | 内容全一致、位置超限 ≤ 5% | 文字是作者写的 |
| ④ 总尺寸 | 图上尺寸数字 vs DXF **实测线段长度** | 最大尺寸必须匹配 | 数字与几何不同源 |

输出 `verify_overlay.png` 差分图：**黑=重合、灰=容差内、红=漏、蓝=多**，一眼可判。
退出码 `0=PASS / 1=WARN / 2=FAIL`。

### 实测基准（一层平面布置图）

- 几何覆盖率 **100.00%**（双向，红 0 像素、蓝 0 像素）
- 文字 194 种全部一致，仅 2 处图签文字临界（字体度量差异）
- 17200→17185.3 / 12800→12796.1 / 9200→9195.0 / 4200→4197.0 全部匹配 → **PASS**

### 读结论的纪律

- **`WARN` 不等于不合格。** 原图**标注值与几何不一致**是会真实发生的
  （本次图为学生课程设计作业）：5500 / 5000 在 DXF 中确实不存在等长线段
  （最接近 5792.5 / 4940.3），那是**原图不是 1:1 画的**，不是复刻错误。
  脚本会打印"最接近的实测长度"供人判断。
- **`PASS` 也不等于可交付。** 必须配一次**人工复核**（CAD 里 `DIST` 抽查、核对文字）。

### 踩过的坑（校验器自身缺陷，务必识别）

| 现象 | 真因 |
|---|---|
| 覆盖率仅 **11.7%**、文字位置差 13 米 | 校验器没做 y 翻转，生成侧做了 → 已改为**方向自动判定** |
| 差分图 **OOM 8.94 GiB** | matplotlib 把大图转 float64 → 已改为块级下采样 + PIL 直写 |
| 文字偏差 795mm、超限 **74 处** | 基准点不一致（左下角 vs 中心）+ 字体度量不同 → 两种基准都试 + 相对容忍度 |
| "外包尺寸"对不上任何数字 | 拿**全图纸**外包框比建筑总尺寸，判据本身错 → 改为比**等长线段** |

> **教训：校验器自身的正确性也必须被审视。** 第一轮 FAIL 若浅尝辄止，
> 会误判成"复刻错了"，而实际上是校验器的坐标系假设错了。

## 七、已知局限

- 转绘路线**不重建语义**：转出的墙是普通多段线，不是参数化墙体；改墙厚要手动。
- 线宽分组（GB 0.5b/0.25b/0.13b）在原 PDF 若已被压成同一线宽，则无法还原，需人工归层。
- 位图路线对**低分辨率、有噪声、有底纹**的扫描件效果差；建议先做二值化与去噪预处理。
